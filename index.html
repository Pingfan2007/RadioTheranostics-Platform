    Methods & provenance

    How this graph is built

    A transparent pipeline from Markdown pages to a typed property graph, with the limitations of the snapshot written down instead of hidden.

    Source

    The knowledge base is an offline Markdown export of RadioPharm, a database of radiopharmaceuticals from IDRlab. Every entity page starts with a typed identifier and a key/value table; drug pages add the nuclide block and the indication list.

    Pipeline

    1. Parse — 4,344 entity pages are read from seven folders; IDs come from the page header, with the catalog CSV as fallback.
    2. Resolve — drug references to nuclides, targets and indications are matched to catalogued entities by normalised name.
    3. Back-fill — five chelator pages in the snapshot truncate their drug list at 50 entries; those lists are completed from the public RadioPharm endpoint and cached.
    4. Serialise — the graph is written as a compact JSON payload (data/kg.json) and rendered client-side on a canvas.

      Palette

      Stack

      • Static HTML, CSS and ES2020 — no framework, no build step, no runtime dependency.
      • Canvas renderer with a radial ego layout, greedy label placement and pan / zoom / hover hit-testing.
      • tools/build_kg.py rebuilds data/kg.json from the Markdown snapshot; the graph loads in about 40 ms.
